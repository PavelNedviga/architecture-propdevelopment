# Задание 3. Внешние интеграции

PropDevelopment хочет расширить бизнес-функции для собственников и жильцов. Компания планирует добавить в систему новые сервисы «Умный дом». Эти сервисы готов предоставить партнёр.


Вы согласовали техническое задание с бизнесом и выбрали две услуги для внедрения:

* **Интеллектуальный домофон**. Включает функции классического видеодомофона — открытие по звонку. Также есть возможность распознавать пользователей по биометрии (по лицу) и автоматически открывать дверь, если им разрешён доступ в дом.
* **Интеллектуальный шлагбаум**. Включает функции классического управления шлагбаумом и автоматически открывает доступ, если распознаёт номера автомобилей, которым въезд разрешён.

Новые сервисы должны быть доступны через текущее мобильное приложение, которое используют собственники.

## Что нужно сделать

1. **Подготовьте диаграмму контекста в модели С4**. Она должна отражать контекст, в котором будут работать новые бизнес-функции.
2. **Доработайте диаграмму контейнеров PropDevelopment**. Отразите на ней изменения, которые вы предлагаете сделать в ландшафте систем кампании в связи с внедрением новых бизнес-функций.
3. **Сформируйте список требований**, которым должны удовлетворить внешние интеграции. Для этого:

   * опишите требования к безопасности,
   * выделите протоколы аутентификации и авторизации,
   * опишите, как будет организовано взаимодействие между системами предприятия и внешней платформой.

Когда выполните задание, загрузите в директорию **Task3** диаграмму контекста, обновлённую диаграмму контейнеров и список требований.

## Решение

Диаграммы контекста представлено не было, потому решил представить ее в нотации plantuml, показав только ядро PropDevelopment + новые сторонние сервисы.

```plantuml
@startuml ContextDiagram

!includeurl https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml

System_Ext(faceGateway, "Интеллектуальный домофон (edge‑устройство)", "Устройство на входной двери, подключено к SmartHome Cloud")
System_Ext(barrierGW, "Интеллектуальный шлагбаум (edge‑устройство)", "Устройство шлагбаума, подключено к SmartHome Cloud")

Rel(systemLandscape, smartHomeCloud, "GraphQL / REST API (через Smart‑home gateway)", "TLS 1.3 + OAuth2")
Rel(smartHomeCloud, faceGateway, "WebSocket / MQTT")
Rel(smartHomeCloud, barrierGW, "WebSocket / MQTT")

@enduml
```

Диаграмма контенеров представлена доработанной в отдельной вкладке [drawio](PropDevelopment_С4_model.drawio)

### Требования к внешним интеграциям умного дома

| Раздел | Требования  |
| -- | -- |
| **Защита соединения** | • Все запросы между `smart-home-gateway-app` и SmartHome Cloud — только по **TLS 1.3** с обязательной **mTLS** (обмен сертификатами). <br>• Минимальный набор шифр-свитов — TLS_AES_128_GCM_SHA256.  |
| **Аутентификация** | • Внешние API — **OAuth 2.1 (client_credentials)**: gateway получает JWT-access-token у Auth-server партнёра. <br>• Внутренние вызовы мобильного приложения — **OIDC + JWT** через существующий `auth-service`. <br>• Допустима PKCE-авторизация для мобильного клиента.  |
| **Авторизация** | • Внутри PropDevelopment действует **RBAC + ABAC**: право «UnlockDoor», «OpenBarrier» хранится в CRM; `smart-home-gateway-app` проверяет токен + атрибуты жилья/машины. <br>• У устройства в подъезде доступ только к дому/секции через device-scoped API-key, ротация ключей — 1 сутки. |
| **Токены / ключи** | • Хранить client-secret, device-keys в **Vault / HSM**; в контейнеры передавать через CI/CD-секреты. <br>• Ротация каждые 90 дней либо при инциденте.  |
| **Логирование и SIEM** | • Gateway в реальном времени отправляет в корпоративный **SIEM** события: попытка доступа, успех/отказ биометрии, открытие шлагбаума. <br>• Формат — JSON + Syslog TLS.  |
| **Сетевое размещение** | • `smart-home-gateway-app` развёрнут в **DMZ-зоне**; исходящие только к SmartHome Cloud, входящие — только от `mobile-gateway`.  |
| **Rate-limit / DDoS** | • Ограничение 30 req/s на домофон, 10 req/s на шлагбаум; автоматический блок по IP при аномалиях.  |
| **Контроль целостности** | • Подпись прошивок устройств партнёра; обновления — через OTA только по TLS, проверка подписи до установки.  |
| **Privacy / ПДн** | • Биометрические шаблоны лиц и номера машин **хранятся только в SmartHome Cloud** (оператор-партнёр, 152-ФЗ ст. 10.1) — PropDevelopment получает лишь ID-события.  |
| **SLA и мониторинг** | • Доступность API ≥ 99.5 %. <br>• Webhook об аварийных событиях — ≤ 60 с.  |
| **Fail-safe** | • При недоступности партнёра мобильное приложение предлагает классическое открытие по звонку/карте.  |
| **Пентест и аудит** | • Партнёр обязуется ежегодно предоставлять отчёт OWASP IoT, результаты пентеста, а также содействовать внешнему аудиту PropDevelopment.  |
